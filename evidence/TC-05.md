# TC-05 — desativação só após sucesso total

- Data UTC: 2026-10-10
- Mecanismo: Manual Trigger no editor n8n; consultas SQL pelo `P01 | DB Read (TEMP)`.
- Resultado: **PASS**. Cada passo criou uma run nova `succeeded`; `07 | Reconcile Repositories` e `07 | Complete Run` executaram uma vez por passo.

| Passo | Modo/cenário | Execução n8n | Run | Páginas / registros | Desativados | Ativos reais | Ativos fixture 2001–2003 |
|---|---|---:|---:|---:|---:|---:|---:|
| live_initial | live / happy | 397 | 18 | 1 / 67 | 3 | 67 | 0 |
| simulator_happy | simulator / happy | 403 | 19 | 2 / 3 | 67 | 0 | 3 |
| live_final | live / happy | 412 | 20 | 1 / 67 | 3 | 67 | 0 |

## Asserções SQL

1. Após o primeiro live: 67 IDs reais ativos e os 3 IDs do fixture inativos.
2. Após simulator happy (duas páginas): 67 IDs reais inativos, 3 IDs do fixture ativos, `records_deactivated=67`.
3. Após o live final: os 67 IDs reais voltaram a `is_active=true`; os 3 IDs do fixture ficaram inativos.
4. Os IDs das runs são distintos e crescentes (18, 19, 20), cada uma com contadores próprios.

```sql
SELECT id, owner_login, status, pages_fetched, records_received, records_inserted, records_updated, records_deactivated FROM public.sync_runs WHERE id IN (18,19,20) ORDER BY id;
SELECT count(*) AS total, count(*) FILTER (WHERE github_repo_id IN (2001,2002,2003) AND is_active) AS fixture_active, count(*) FILTER (WHERE github_repo_id NOT IN (2001,2002,2003) AND is_active) AS live_active, count(*) FILTER (WHERE github_repo_id IN (2001,2002,2003) AND NOT is_active) AS fixture_inactive, count(*) FILTER (WHERE github_repo_id NOT IN (2001,2002,2003) AND NOT is_active) AS live_inactive FROM public.github_repositories;
```
